# 项目维护者申请与要求

项目维护者负责让一个项目持续有人响应、能够协作，而不只是拥有仓库权限。

## 基本要求

- 已经参与过相关项目，或能提供与项目相关的公开作品和实践经历；
- 能够持续关注项目，处理 Issue、审核 PR，并及时说明无法继续维护的情况；
- 理解项目 README、许可证、安全边界和第三方素材要求；
- 能够给贡献者清楚、尊重且可执行的反馈；
- 遵守社区行为准则，主动说明利益冲突，不滥用仓库和组织权限。

## 主要工作

- 整理新手可以参与的任务；
- 确认 Issue 的目标和验收标准；
- 审核代码、设计、产品、测试、文档和内容贡献；
- 维护项目说明、许可证、版本状态和安全边界；
- 在项目暂停、转交或结束维护时公开说明。

## 申请流程

1. [提交维护者申请](https://github.com/shengjidaguai-china/.github/issues/new?template=maintainer-application.yml)，说明想维护的项目、相关经历、可以投入的时间和维护计划；
2. 由现有维护者或社区主理人公开沟通职责和权限范围；
3. 新维护者先从 Issue 整理、PR Review 或单一仓库的具体工作开始；
4. 根据实际参与情况授予或调整必要权限。

社区遵循最小权限原则。维护一个项目不会自动获得整个组织的管理权限。完整规则见[社群治理规则](./GOVERNANCE.md)。

# Maintainer requirements and application

A project maintainer keeps a project responsive and collaborative. The role is about ongoing responsibility, not merely repository access.

## Basic requirements

- Prior involvement in the project, or public work and practical experience relevant to it;
- Capacity to monitor the project, handle issues, review pull requests, and communicate when continued maintenance is no longer possible;
- Understanding of the project's README, license, security boundaries, and third-party material requirements;
- Clear, respectful, and actionable feedback for contributors;
- Compliance with the Code of Conduct, disclosure of conflicts of interest, and responsible use of repository and organization permissions.

## Main responsibilities

- Prepare tasks that beginners can pick up;
- Clarify issue goals and acceptance criteria;
- Review code, design, product, testing, documentation, and content contributions;
- Maintain project documentation, license information, status, and security boundaries;
- Publicly communicate when maintenance is paused, transferred, or ended.

## Application process

1. [Submit a maintainer application](https://github.com/shengjidaguai-china/.github/issues/new?template=maintainer-application.yml) with the target project, relevant experience, available time, and maintenance plan;
2. Discuss responsibilities and permission scope with an existing maintainer or the community organizer;
3. Start with concrete work such as issue triage, pull-request review, or a single repository;
4. Receive or adjust only the permissions needed for the work, based on actual participation.

The community follows the principle of least privilege. Maintaining one project does not automatically grant organization-wide administration rights. See the [community governance rules](./GOVERNANCE.md) for details.
